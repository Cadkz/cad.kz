# Демо на Vercel и Neon: пошаговая инструкция

Цель: получить ссылку на демо-сайт, которую можно показать коллегам. Всё бесплатно, аккаунты вы создаёте сами. Действующий cad.kz не затрагивается. В демо покупатели оставляют заявки только в учебную базу, менеджерам ничего не уходит, поисковики сайт не индексируют.

Не присылайте в переписку пароли, строки подключения и ключи: ни мне, ни в чат. Они вводятся только на сайтах Vercel и Neon и в файле `.env` на вашем компьютере.

## Что понадобится
- Аккаунт GitHub (он у вас есть) и доступ к репозиторию Cadkz/cad.kz.
- Около 40 минут.
- Одна программа на компьютере: Node.js (шаг 3). Нужна один раз, чтобы создать таблицы и загрузить демоданные.

## Шаг 0. Решите вопрос с репозиторием
Бесплатный тариф Vercel не умеет брать код из закрытого репозитория, который принадлежит организации (у нас именно так). Выберите один из трёх путей:
1. Сделать репозиторий открытым. Бесплатно, быстро. Код и папка `docs` станут видны всем в интернете. Секретов в репозитории нет, но решите, готовы ли показать план и макеты. После демо можно снова закрыть.
2. Перенести репозиторий на личный аккаунт GitHub (Settings → Danger Zone → Transfer). Бесплатно, закрытым остаётся.
3. Платный тариф Vercel Pro (около 20 долларов в месяц за пользователя).

Бесплатный тариф Vercel Hobby разрешён только для некоммерческого использования. Для внутренней демонстрации это нормально; рабочий сайт на нём запускать нельзя.

## Шаг 1. База данных в Neon
1. Откройте neon.com, нажмите «Sign up» и войдите через GitHub.
2. Создайте проект: имя `cad-kz-demo`, регион Европа (Frankfurt), остальное по умолчанию.
3. На странице проекта нажмите «Connect». Появится длинная строка, которая начинается с `postgresql://`. Нажмите «Copy snippet» или скопируйте строку целиком. Оставьте переключатель пула подключений включённым, как есть.
4. Сохраните строку во временный файл на своём компьютере. Она нужна на шагах 3 и 4.

## Шаг 2. Придумайте два секрета
- Секретный ключ сайта: длинный набор случайных символов. Самый простой способ получить его описан на шаге 3 (команда ниже).
- Пароль администратора: не короче 16 символов, только для этого демо. Почта администратора — любая ваша.

## Шаг 3. Подготовка базы с вашего компьютера
Этот шаг создаёт таблицы и загружает демоданные в Neon. Делается один раз.
1. Установите Node.js: сайт nodejs.org, кнопка LTS, установщик, везде «Далее». Установите Git: git-scm.com, тоже «Далее».
2. Откройте терминал (Windows: меню «Пуск» → «PowerShell»; Mac: программа «Терминал»).
3. Выполните по очереди (после каждой строки Enter):
   ```
   corepack enable
   git clone https://github.com/Cadkz/cad.kz.git
   cd cad.kz
   pnpm install
   ```
   Если репозиторий закрытый, GitHub попросит войти в аккаунт. Если на `corepack enable` Windows пишет про нехватку прав, откройте PowerShell от имени администратора и повторите.
4. Получите секретный ключ командой и скопируйте то, что она напечатает:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
5. В папке `cad.kz` создайте файл `.env` (в блокноте, без расширения .txt) с такими строками. Вместо слов в скобках вставьте свои значения:
   ```
   DATABASE_URL=(строка из Neon)
   PAYLOAD_SECRET=(ключ из пункта 4)
   APP_MODE=demo
   BOOTSTRAP_ADMIN_EMAIL=(ваша почта)
   BOOTSTRAP_ADMIN_PASSWORD=(пароль из шага 2)
   ```
   Файл `.env` не попадает в GitHub, его никому не отправляйте.
6. Запустите одну команду:
   ```
   pnpm demo:setup
   ```
   В конце должно быть «Готово». Команду можно запускать повторно: таблицы не задвоятся, демоданные обновятся до исходных (правки демотоваров в админке при этом сбросятся).
7. Откройте `.env` и удалите две строки `BOOTSTRAP_ADMIN_…`.

## Шаг 4. Сайт на Vercel
1. Откройте vercel.com, «Sign Up» → «Continue with GitHub». Выберите тариф Hobby.
2. «Add New…» → «Project», найдите репозиторий `cad.kz`, нажмите «Import». Если репозитория нет в списке, нажмите «Adjust GitHub App Permissions» и разрешите доступ к нему.
3. Не нажимая Deploy, раскройте блок «Environment Variables» и добавьте четыре переменные (имя слева, значение справа):

   | Имя | Значение |
   | --- | --- |
   | `DATABASE_URL` | строка из Neon, та же, что в `.env` |
   | `PAYLOAD_SECRET` | тот же ключ, что в `.env` |
   | `APP_MODE` | `demo` |
   | `MEDIA_STORAGE` | `blob` |

4. Нажмите «Deploy» и дождитесь «Congratulations». Это 2–4 минуты.
5. Подключите хранилище картинок: в проекте вкладка «Storage» → «Create Database» → «Blob» → создать → «Connect Project» и выберите этот проект. Vercel сам добавит ключ `BLOB_READ_WRITE_TOKEN`.
6. Вкладка «Deployments» → у верхней записи три точки → «Redeploy». Нужно, чтобы сайт увидел новый ключ.

## Шаг 5. Проверка, что всё работает
Откройте адрес проекта (вида `cad-kz-….vercel.app`) и пройдите список:
1. Главная открывается, в каталоге есть товары.
2. Адрес `…/robots.txt` показывает `Disallow: /`: сайт закрыт от поисковиков.
3. Добавьте товар в корзину, перейдите к оформлению, заполните форму (БИН для проверки: 971240001315), отправьте. Должно появиться «Заявка сохранена. В демоверсии она не передаётся менеджерам.» и номер заявки.
4. Адрес `…/admin`: войдите почтой и паролем администратора. В разделе «Заказы» есть ваша заявка, внутри видны состав и цены на момент оформления.
5. В «Медиа» загрузите картинку (до 4 МБ), прикрепите к новости как обложку. Картинка показывается на сайте, адрес картинки содержит `blob.vercel-storage.com`.

Если что-то не сработало, пришлите мне текст ошибки или скриншот. Строки подключения и пароли в скриншоте закрывайте.

## Что важно знать
- Первая загрузка после простоя может идти несколько секунд: бесплатная база Neon засыпает. Перед показом откройте сайт за минуту.
- Админка на бесплатном Vercel может открываться медленнее обычного.
- Картинки больше 4 МБ загрузить не получится: перед загрузкой сожмите.
- Письма не отправляются, в Bitrix24 заявки не уходят. Это сделано намеренно и написано на сайте.
- Каждое изменение в ветке main на GitHub само обновляет сайт на Vercel. Если в изменении есть новая миграция (файл в `src/migrations`), перед обновлением нужно выполнить на компьютере `pnpm migrate` с тем же `.env`. Об этом я напишу в описании изменения.
- Если строка подключения или пароль попали куда не следует: в Neon сбросьте пароль роли (Settings → Roles → Reset password), обновите `DATABASE_URL` на Vercel и в `.env`, нажмите Redeploy.

## Как это устроено для разработчиков
- Таблицы на хостинге меняют только миграции из `src/migrations` (`pnpm migrate:create` создаёт, `pnpm migrate` применяет). Автоподгонка Payload (push) включена только в разработке и отключается при `NODE_ENV=production` или `DB_SCHEMA_MODE=migrate`. Перед созданием новой миграции схема базы должна соответствовать последней применённой.
- `pnpm demo:setup` = миграции, демоданные (`scripts/seed-demo.mjs`, только `APP_MODE=demo`), первый администратор (`scripts/bootstrap-admin.mjs`, только в пустой базе).
- Картинки CMS: `MEDIA_STORAGE=blob` включает Vercel Blob (`@payloadcms/storage-vercel-blob`), без переменной картинки лежат в папке `media`. Адреса `*.public.blob.vercel-storage.com` разрешены для `next/image` в `next.config.mjs`.
- Индексация закрыта тремя способами: `robots.txt`, мета-тег `robots` и заголовок `X-Robots-Tag` на всех адресах при `APP_MODE=demo`.
- Сайт собирается и на пустой базе: сборка не обращается к таблицам.

## Перенос на VPS в Казахстане
Позже сайт можно перенести без привязки к Vercel и Neon: нужен сервер с Node.js и PostgreSQL (или Docker). Переносятся код, дамп PostgreSQL, картинки и настройки окружения; `MEDIA_STORAGE` для этого оставляют пустым, картинки лежат в папке `media`. Перед переключением домена проверить миграции, восстановление данных, HTTPS, резервные копии. Обычный PHP-хостинг не подойдёт. Тестовая и рабочая базы раздельные, секреты задаются на площадке, не в репозитории.

## Проверка скорости
Не обещать ускорение только из-за смены CMS. Сравнить действующий и новый сайт одинаковыми устройством, сетью и географией, отдельно холодную и повторную загрузку. Проверять главную, каталог, товар и статью; оценивать LCP, INP, CLS, TTFB, вес изображений/JS и запросы каталога.
Целевые ориентиры перед презентацией: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на согласованном мобильном профиле. Это цели, не текущие измерения. Полевые метрики 75-го перцентиля потребуют реального трафика; локальный Lighthouse их не заменяет.
Публичные страницы/контент можно кэшировать; итоговые цены, корзина и оформление проверяются сервером по актуальным данным. Для ИИ отдельно измерять время первого ответа: оно не должно блокировать открытие каталога.
