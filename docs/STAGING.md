# Демо на Vercel и Neon: пошаговая инструкция

Цель: ссылка на демо-сайт, которую можно открыть с любого устройства. Всё бесплатно, аккаунты создаёте вы сами. Действующий cad.kz не затрагивается. В демо заявки сохраняются в учебную базу и менеджерам не передаются, поисковики сайт не индексируют. Терминал и установка программ не нужны: все действия делаются в браузере.

Пароли и строки подключения вводятся только на сайтах Vercel и Neon. В переписку, в чат и в GitHub их присылать нельзя.

## Шаг 1. Открыть репозиторий (1 минута)
Бесплатный Vercel не берёт код из закрытого репозитория организации, поэтому репозиторий делаем открытым.
1. Откройте github.com/Cadkz/cad.kz → вкладка «Settings».
2. Прокрутите до самого низа, блок «Danger Zone» → «Change repository visibility» → «Change to public» и подтвердите.

Я проверил историю репозитория: паролей, ключей и файлов `.env` там нет. Откроются код, папка `docs` и макеты. После демо репозиторий можно снова закрыть.

Бесплатный тариф Vercel Hobby разрешён только для некоммерческого использования. Для внутреннего показа подходит, рабочий сайт на нём запускать нельзя.

## Шаг 2. База данных в Neon (5 минут)
1. Откройте neon.com, нажмите «Sign up» и войдите через GitHub.
2. Создайте проект: имя `cad-kz-demo`, регион Европа (Frankfurt), остальное оставьте как есть.
3. На странице проекта нажмите «Connect». Появится длинная строка, которая начинается с `postgresql://`. Скопируйте её целиком и никуда не отправляйте. Она понадобится на следующем шаге.

## Шаг 3. Сайт на Vercel (10 минут)
1. Откройте vercel.com, «Sign Up» → «Continue with GitHub», тариф Hobby.
2. «Add New…» → «Project», найдите `cad.kz`, нажмите «Import». Если репозитория нет в списке, нажмите «Adjust GitHub App Permissions» и разрешите доступ к нему.
3. Раскройте «Build and Output Settings», у строки «Build Command» включите «Override» и впишите `pnpm run vercel-build`.
4. Не нажимая Deploy, раскройте блок «Environment Variables» и добавьте переменные. Имя пишется слева, значение справа, после каждой нажимайте «Add»:

   | Имя | Значение |
   | --- | --- |
   | `DATABASE_URL` | строка из Neon |
   | `PAYLOAD_SECRET` | любой длинный набор случайных символов, 40 и больше (например, нажмите на клавиатуре пальцами случайно 40 букв и цифр) |
   | `APP_MODE` | `demo` |
   | `DEMO_AUTO_SETUP` | `yes` |
   | `MEDIA_STORAGE` | `blob` |
   | `BOOTSTRAP_ADMIN_EMAIL` | ваша почта для входа в админку |
   | `BOOTSTRAP_ADMIN_PASSWORD` | пароль для админки, не короче 16 символов |

5. Нажмите «Deploy» и подождите 3–5 минут. При первой сборке сайт сам создаст таблицы, загрузит демоданные и заведёт вас как администратора. Повторные сборки данные не трогают.
6. Подключите хранилище картинок: в проекте вкладка «Storage» → «Create Database» → «Blob». В окне выберите доступ «Public» (не Private, сайт отдаёт картинки по ссылке) и поставьте галочку «Add a read-write token env var to this connection», затем «Create» и подключите к проекту `cad-kz`. В «Settings» → «Environment Variables» должна появиться `BLOB_READ_WRITE_TOKEN`.
7. Вкладка «Deployments» → у верхней записи три точки → «Redeploy», чтобы сайт увидел ключ.
8. Когда всё работает, в «Settings» → «Environment Variables» удалите `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`: они нужны только для первой сборки.

## Шаг 4. Проверка
Откройте адрес проекта (вида `cad-kz-….vercel.app`) и пройдите список:
1. Главная открывается, в каталоге есть товары.
2. Адрес `…/robots.txt` показывает `Disallow: /`: сайт закрыт от поисковиков.
3. Добавьте товар в корзину, откройте оформление, заполните форму (для проверки БИН подойдёт 971240001315), отправьте. Должно появиться «Заявка сохранена. В демоверсии она не передаётся менеджерам.» и номер заявки.
4. Адрес `…/admin`: войдите почтой и паролем из шага 3. В разделе «Заказы» есть ваша заявка, внутри видны состав и цены на момент оформления.
5. В «Медиа» загрузите картинку (до 4 МБ) и прикрепите к новости как обложку. Адрес картинки на сайте содержит `blob.vercel-storage.com`.

Если что-то не сработало, пришлите текст ошибки со страницы Vercel (вкладка «Deployments» → «Build Logs»). Строки подключения и пароли в тексте закройте.

## Что важно знать
- Первая загрузка после простоя идёт несколько секунд: бесплатная база Neon засыпает. Перед показом откройте сайт за минуту.
- Картинки больше 4 МБ загрузить не получится, сожмите перед загрузкой.
- Письма не отправляются, в Битрикс24 заявки не уходят. Это сделано намеренно и написано на сайте.
- Каждое изменение в ветке main на GitHub само обновляет сайт на Vercel. Новые миграции применяются при той же сборке.
- Если строка подключения или пароль попали куда не следует: в Neon сбросьте пароль роли (Settings → Roles → Reset password), обновите `DATABASE_URL` на Vercel и нажмите Redeploy.

## Как это устроено для разработчиков
- Таблицы на хостинге меняют только миграции из `src/migrations` (`pnpm migrate:create <имя>` создаёт, `pnpm migrate` применяет). Создавать миграции только этой командой: она включает схему как на хостинге (плагин Vercel Blob добавляет столбец в таблицу media). Автоподгонка Payload (push) включена только в разработке и отключается при `NODE_ENV=production` или `DB_SCHEMA_MODE=migrate`. Перед созданием новой миграции схема базы должна соответствовать последней применённой.
- Сборка на Vercel идёт через `scripts/vercel-build.mjs`. При `DEMO_AUTO_SETUP=yes` и `APP_MODE=demo` она вызывает `scripts/demo-setup.mjs --first-time`: миграции, демоданные только в пустой каталог, первый администратор только в пустой таблице пользователей. Без `DEMO_AUTO_SETUP` выполняется обычный `next build`. Для рабочего сайта автонастройку не включать.
- Вручную то же самое делает `pnpm demo:setup` (строка подключения и пароль в локальном `.env`, он не попадает в git); без ключа `--first-time` демоданные обновляются до исходных.
- Картинки CMS: `MEDIA_STORAGE=blob` включает Vercel Blob (`@payloadcms/storage-vercel-blob`), без переменной картинки лежат в папке `media`. Адреса `*.public.blob.vercel-storage.com` разрешены для `next/image` в `next.config.mjs`.
- Индексация закрыта тремя способами: `robots.txt`, мета-тег `robots` и заголовок `X-Robots-Tag` на всех адресах при `APP_MODE=demo`.
- Сайт собирается и на пустой базе: сборка не обращается к таблицам.

## Перенос на VPS в Казахстане
Позже сайт можно перенести без привязки к Vercel и Neon: нужен сервер с Node.js и PostgreSQL (или Docker). Переносятся код, дамп PostgreSQL, картинки и настройки окружения; `MEDIA_STORAGE` для этого оставляют пустым, картинки лежат в папке `media`. Перед переключением домена проверить миграции, восстановление данных, HTTPS, резервные копии. Обычный PHP-хостинг не подойдёт. Тестовая и рабочая базы раздельные, секреты задаются на площадке, не в репозитории.

## Проверка скорости
Не обещать ускорение только из-за смены CMS. Сравнить действующий и новый сайт одинаковыми устройством, сетью и географией, отдельно холодную и повторную загрузку. Проверять главную, каталог, товар и статью; оценивать LCP, INP, CLS, TTFB, вес изображений/JS и запросы каталога.
Целевые ориентиры перед презентацией: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на согласованном мобильном профиле. Это цели, не текущие измерения. Полевые метрики 75-го перцентиля потребуют реального трафика; локальный Lighthouse их не заменяет.
Публичные страницы/контент можно кэшировать; итоговые цены, корзина и оформление проверяются сервером по актуальным данным. Для ИИ отдельно измерять время первого ответа: оно не должно блокировать открытие каталога.
