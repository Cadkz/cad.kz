# Тестовый адрес и будущий перенос

Согласованное направление: сначала отдельный тестовый сайт для проверки/презентации и отправки ссылки, затем возможный перенос на VPS в Казахстане. Действующий cad.kz не меняем. Хостинг-провайдер, тариф и аккаунт ещё не выбраны; внешнего тестового адреса пока нет.

## Как будет устроено
GitHub → проверка тестов и сборки → тестовое окружение с HTTPS и постоянным URL. Это размещённый сервер, доступный без включённого рабочего ПК. До интеграций включён явный demo mode. На тесте — обезличенные данные, отсутствие реальных отправок CRM и запрет индексации; при необходимости ограничение доступа паролем.

Для витрины достаточно Node.js-приложения. Полная проверка /admin и оформления требует PostgreSQL и постоянного хранилища медиа. Репозиторий GitHub сам по себе не является хостингом приложения; статический GitHub Pages не запускает серверный расчёт и Payload.

## Перенос на VPS Казахстана
Использовать переносимый запуск Node.js либо Docker без обязательных сервисов конкретной облачной платформы. Перенести код/сборку, дамп PostgreSQL, медиа и настройки окружения. Перед переключением отдельного домена проверить миграции, восстановление данных, HTTPS, резервные копии и доступность. Для размещения требуется Node.js и PostgreSQL либо поддержка контейнеров: обычный PHP-тариф может не подойти.
Автоматические миграции production-БД не включать. Тестовая и рабочая БД раздельные. Секреты задаются на площадке, не в GitHub-репозитории.

## Проверка скорости
Не обещать ускорение только из-за смены CMS. Сравнить действующий и новый сайт одинаковыми устройством, сетью и географией, отдельно холодную и повторную загрузку. Проверять главную, каталог, товар и статью; оценивать LCP, INP, CLS, TTFB, вес изображений/JS и запросы каталога.
Целевые ориентиры перед презентацией: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на согласованном мобильном профиле. Это цели, не текущие измерения. Полевые метрики 75-го перцентиля потребуют реального трафика; локальный Lighthouse их не заменяет.
Публичные страницы/контент можно кэшировать; итоговые цены, корзина и оформление проверяются сервером по актуальным данным. Для ИИ отдельно измерять время первого ответа: оно не должно блокировать открытие каталога.
